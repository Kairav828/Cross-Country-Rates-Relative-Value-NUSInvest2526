# Regime Contract (Frozen)

## Executive Summary
We have macro-defined regimes (vol/curve/USD/macro) that produce interpretable state labels and persistence, and we will use them to gate conditional cointegration/mean-reversion analysis while explicitly acknowledging where structure-validation metrics are still missing in the saved hypothesis outputs.

## Purpose (what this contract is)
This document **freezes** the regime definition and outputs used downstream (In subsequent phases - involving cointegration, kalman filtering etc).
Regimes must be:
- Macro/volatility defined 
- Independent of cointegration/residuals/trading performance
- Reproducible from data diagnostics and pair selection work + macro inputs only

---

## Research question this contract answers
**Under which macro & volatility regimes do cross country rate relationships remain stable vs structurally break?**

Regimes are used as **gates**:
- Cointegration + Kalman are run **conditional on regimes**
- No “tuning” regimes to improve PnL is allowed

---

## Inputs (allowed features only)

### Frozen feature set (daily, stationary)
All features come from `results/regime_features.csv` generated by `NOTEBOOKS/09_regime_features.ipynb`.

Frozen columns:
- `move_chg` — daily change in MOVE (volatility proxy)
- `dxy_chg` — daily change in DXY (USD stress proxy)
- `curve_signal` — PCA(PC1) of first-differenced 2s10s curve slope signals (global curve factor)
- `macro_surprise` — PCA(PC1) of macro surprise z-score block (global surprise factor)

**Explicitly forbidden features**:
- Yield spreads (cross country spreads, regression residual spreads, cointegration residuals)
- Any subsequent phase outputs (OU residuals, half-life, Kalman innovations, z scores on spreads)
- Any feature engineered using *future* information

---

## Transformations & leakage rules (frozen)

### Alignment
- Daily frequency only
- Inner-join on dates across features
- Features must be lag-safe (no using tomorrow’s macro print to label today)

### Stationarity enforcement
- Use changes / stationary transforms for non-stationary level series:
  - MOVE level → `move_chg` (difference)
  - DXY level → `dxy_chg` (difference)
  - Curve: do not use yield levels directly; use stationary curve-slope changes + PCA
  - Macro: use z-score block + PCA (bounded / standardized)

### Normalization rule
We do not globally standardize to unit variance for “pure ML neatness”.
Instead we preserve economic priority while keeping KMeans init stable:
- VOL (MOVE) is treated as primary regime driver
- Curve is secondary
- USD + macro are contextual modifiers

(See `results/regime_feature_engineering_note.md` for why scaling/feature design was chosen.)

## Model (frozen)

### Model family
- Gaussian Hidden Markov Model (HMM), `hmmlearn.hmm.GaussianHMM`
- Covariance: `full`
- Fit via EM / Baum–Welch (non-convex, initialization-sensitive)
- Model selection via BIC over {2,3,4} states

Implementation reference:
- `src/regimes/hmm.py` (`fit_hmm_models`, `select_best_model`, `extract_regime_labels`, `interpret_states`)

### Frozen selection
**Best model = 4 states** (per BIC), used for all downstream work.

This is frozen unless an explicit OOS protocol later demands retraining.

## Economic meaning (frozen mapping)

We keep the **state numbering fixed** as produced in `results/regime_state_summary.csv`.

### State definitions (from current frozen run)
- **State 0 — Low Volatility / Risk-On**
  - Low MOVE change; normal USD; mild positive macro
- **State 1 — Slowdown / Flattening**
  - Low vol; negative macro surprise; curve tends flatter
- **State 2 — Stable / Positive Surprises**
  - Low vol; strong positive macro surprise
- **State 3 — Crisis / Flight-to-Quality**
  - High MOVE change (dominant); curve shift signal spikes

### Umbrella regime mapping for gating (For Cointegration + Kalman Filtering)
To avoid over-fragmenting the downstream modeling, we define:

- **CALM umbrella = {State 0, State 1, State 2}**
  - Expected environment for stable cross-country structure
  - Candidate for conditional cointegration tests

- **STRESS umbrella = {State 3}**
  - Expected environment for structural breaks / fragmentation
  - Cointegration is *not assumed*; must treat as “break-risk”

---

## How cointegration and kalman filtering must use regimes (hard rules)

### Label usage
Downstream should primarily use:
- `regime_most_likely` for discrete splits
- `P(STRESS) = regime_prob_3` for soft gating

### Recommended gating thresholds (frozen defaults)
- “Stress day” if `regime_prob_3 >= 0.60`
- “Calm day” if `regime_prob_3 <= 0.40`
- 0.40–0.60 treated as “transitional / ambiguous” (report separately)

**These thresholds may be sensitivity-tested in subsequent phase, but not optimized for PnL.**

## Validation status (what this phase successfully established)

### What is validated
- Regimes are interpretable (feature means map to coherent economic narratives)
- Persistence is sensible (transition matrix not random)
- Sensitivity tests exist (`results/regime_stability_metrics.csv`) and instability is documented

### What is NOT fully validated (must be acknowledged)
- “Rolling correlations weaken in stress regimes”: not available due to missing `rolling_corr_mean` in the current validation output
- “Clusters fragment in stress”: not available due to missing clustering fragmentation metric

Therefore, this phase's core claim is:
> Regimes are macro/vol-defined and interpretable; they are designed to *explain* structural breaks, but the correlation/cluster validation is currently incomplete in the saved hypothesis table.

This must be fixed later by wiring the missing structure metrics.
